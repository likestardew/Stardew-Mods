> 模拟器：`sim-v5/Program.cs` = sim-audit1（经审计的修正版）+ 本轮五项建模补充（§1）。

## 1. 建模补充（相对 sim-audit1，全部有源码依据）

### 1.1 双发 poke（已核实并建模）

原版 `performTenMinuteAction`（junimohut.cs:280-296）poke 每只在场祝尼魔（**含收获中**，无 harvestTimer/controller 检查）；mod 的 `ReplaceJunimoTimerNumber` 是同一方法的 postfix（HEAD JunimoHutPatches.cs:265-302），再 poke 一遍。→ 每只每 430t **两次独立** poke，各自 70% 门、各自过限速门。基座只建了单发，会低估原版的同步突发。

### 1.2 WorkFaster + WorkRidiculouslyFast（用户真实配置，主场景；出处与逐条推演见 DESIGN.md §0.2）

- 收获周期**不变**（`PatchTryToHarvestHere` 对收获恒 `time=2000`；`PatchJunimoShake` 的 `==999` 跳过需要 1000ms 跨越帧恰好落在 999，即从 2000 起累计耗时恰为 1001ms——每帧 ~16ms 的整步递减到不了 999，只有帧抖动才可能命中，属彩票路径，建模为不触发）。
- `PatchPokeToHarvest` postfix（faa40d4:293-297）：destroy=false 且 controller=null 时**无条件** `pathfindToNewCrop`。三个后果全部建模：(a) 收获计时归零后 100% 决策；(b) 死到达立即 100% 决策 + WorkFaster 把"无事可做"计时器 200ms→5ms（重 poke 从 +12t 提前到 +1t）；(c) 430t poke 打中收获中祝尼魔 → 阶段 0 = 原地重开（**计时器重置**，反编译逐帧推演：搜索返回含起点的路径 pfc.cs:296-304 → 下一帧 moveCharacter 立即 Pop → tryToHarvestHere 重置 harvestTimer）、阶段 1 = 提前结束空站；被限速拦截时免打扰。
- 3.5% 闲逛被 WRF 移除（faa40d4:254）。

**WRF 对结论形态的影响（重要）**：WRF 让无认领算法的扎堆 churn 放大（cap_only 的 doomed 到达在茂密田达 ~2000/局、清场被拖到与原版持平或更差），认领过滤的价值相应放大。模型里补丁的清场优势（−24%~−70%）**远大于实测（≈持平）**——模型外因素（真实农田障碍/浇水等能力混布、10 分钟粒度的实测口径、祝尼魔碰撞等）会压缩这一差距；跨模型绝对值不可直接外推，本报告的交付物是**同模型内的算法间对比**。

### 1.3 清场分期统计

按"已清 0-25/25-50/50-75/75-100%"四段记录每段用时与 A* expansions（`ph{1..4}_t/_p`），外加全程最差 60t（1s）A* 窗口 `peak60`（吞吐局也记录）。

### 1.4 双小屋重叠场景

小屋 A(28,32)、B(52,32)，radius 14（29×29 盒，重叠 5 列 ≈145 格），每小屋 6 只（共 12），density {0.75, 1.00}。每小屋独立：门控扫描缓存 / lkc / 生成节流 / v5 verdict；**认领表全局共享**（CropClaims 是静态 (location,point) 表）；终点超出自己小屋的盒 → 出盒判定丢弃（真实 `outsideRadius` 语义，单小屋恒不触发）。

### 1.5 v5 计数扫描的早退（真实 DLL 成本的关键）

v5 需要小屋知道"盒内可动作格数"，但 mod 的扫描早期退出正是为了省成本（HEAD JunimoHutPatches.cs 注释）。解法：计数扫描在找到 `max(k,m)×jn + 1` 个可动作后即停——茂盛期只扫几十格，稀疏期才全盒扫（与现有门控在空盒时的成本相同，**不引入新的最坏情形**）。终版网格实测 scan_ops：cap_only 23.5k vs **v5_k1 20.9k**（d=1.00, jn=6 清场局）——v5 的扫描开销与不计数版本同界。

## 2. v5 的三个修复（精确语义与伪代码见 DESIGN.md）

1. **条件化去重（k=1）**：小屋 60t 缓存扫描计数 ≤ 1×每小屋祝尼魔数 → 本次决策关闭认领过滤、退回原版贪婪。
2. **末期回退（m）**：与修复 1 是**同一机制**（同一阈值条件）；数据上 m=1 ≡ k=1、m=2 ≡ k=2，参数保留以便日后分别调。
3. **拥挤判定缓存（T=40）**："过滤搜索跑满预算仍全是他人认领"的判定按小屋缓存 40t；期间后续决策**跳过注定失败的过滤搜索**、直接跑无过滤影子搜索（目标完全相同，拥挤决策 A* 减半）；任一过滤成功即失效；终点实测未被认领时自愈为正常认领路径。

## 4. 对实测两个缺口的检验（如实评估）

### 4.1 "清场期补丁卡顿尖峰更多" —— 找到了模型中的对应物，v5 将其基本消除

- **"饱和清场期补丁 A* 是原版 2~3 倍"在修正+WRF 模型下不成立，方向相反**：v4b 的饱和段（p1）A* 是 cap_only（同限速同门控、无过滤 twin）的 **0.38~0.80 倍**（p2 0.26~0.94；过滤消灭了扎堆 churn 的重复决策）；过滤的 A* 代价只在尾段部分格子出现（p4 0.56~1.51 倍）。旧"2~3x"是审计前旧节奏模型的产物（与 audit REPORT §8 的存疑判定一致）。
- **尖峰的可靠信号在峰值窗口**：v4b 的最差 1s A* 窗口 = cap_only 的 **1.05~1.56 倍**（清场格）/ **1.31~1.50 倍**（CPU 日格）——拥挤时的"过滤失败 + 全预算影子重搜"恰好叠加在双发 poke 的同步突发上，这是玩家可感帧尖峰的候选来源；不过 v4b 峰值仍低于原版（清场格 0.39~0.77×、日格 0.41~0.60×），因为原版扎堆 churn 本身更重。这可以解释实测的并存现象：补丁平均 FPS 更高（22.5 vs 20）但"尖峰体感更多"——平均收益来自 cap，尖峰来自过滤。
- **v5 的效果**：peak60 相对 v4b **−13~−35%**（清场格：0.10/8 1912→1251、0.10/6 1443→1003、1.00/6 1288→926；日格 0.05/6 2032→1371 即 −33%、双小屋 0.05/6 3311→2247 即 −32%），落到 cap_only 的 **0.73~1.20 倍**（清场格）/ **0.99~1.24 倍**（日格），对原版 **0.39~0.55 倍**。**认领过滤的峰值代价被基本移除**（日格 8 格中 5 格已 ≤ cap_only）。

### 4.2 "越到后面效率越低" —— 部分复现，且强烈依赖田块形状；v5 未改善该指标（如实）

- **反转的部分**：双小屋重叠田方向相反——legacy 自身 p4/p2 高达 2.35（原版火车在 12 只争用下尾段崩塌），v4b 只有 1.56~1.69。田块形状决定谁在末期吃亏。
- **绝对值**：尾段（p4）用时 v4b 仍比 legacy 快 **−8%（0.10/2）~ −69%（0.75/8）**（茂密格 −33~−69%，双小屋 −54~−59%，稀疏格 −8~−31%）。"补丁末期比原版慢"在模型中不成立。
- **三个修复对该指标的效果（如实）**：k/m（退回原版贪婪）把影子行走换成 doomed 陪站，p4/p2 **不降反微升**（+0.02~0.22）；D 无感；T 只削 A* 不减影子行走。**v5 未修复相对劣化**——但把尾段的 A*/峰值代价削掉（v5k1/cap 的 p4 pops 0.56~1.20 vs v4b 的 0.56~1.51，多数格明显下降），且日稳态（波间稀疏 = 另一种"活少"）CPU 因 k 阈值多省 6~15 个百分点（v4b −20~−34% → v5 −33~−44%），这是"活少时关闭过滤"设计意图真正兑现的地方。若要彻底解决相对劣化，方向不在过滤开关，而在认领释放时机（如"起走即释放"）——超出本轮范围，未验证。

## 5. 结论

1. **v5 = k1 + T40**（条件化去重阈值 1×每屋祝尼魔数 + 拥挤判定缓存 40t；末期回退 m 与 k 同机制并入）：14 个清场格 + 8 个 CPU 日格、n=50/30 配对下——
   - 清场相对原版 **−24%~−70%**（与 v4b 差 ≤4pp、多数 ≤1pp）；
   - 日稳态 A* **−33%~−44%**（v4b 为 −20%~−34%），双小屋同样成立；
   - 最差 1s 窗口比 v4b **−7~−35%**，回落到无过滤 twin 的 0.73~1.24 倍——**认领过滤的峰值代价被基本移除**，这是对实测"尖峰多"的针对性修复；
   - 防扎堆保持（doomed 为原版 0.2~7.8%，量级不变）；DNF=0、无死锁、扫描开销与现有门控同界。
2. **"饱和期 A* 2~3x"被修正模型推翻**：修正节奏 + WRF 下，过滤在饱和段把 A* 降到无过滤 twin 的 0.38~0.80 倍；补丁的 A*/峰值代价集中在**尾段与拥挤突发**，v5 的 T 节流正面命中。
3. **"越到后面效率越低"部分复现**：补丁自身 p4/p2 = 1.18~1.43（茂密田）~2.8（稀疏田），多数格高于原版同口径；但绝对尾段速度仍比原版快 8~69%。**三个修复未能缩小该相对劣化（数据如实，v5 略有放大）**；其可修的部分（尾段 A*/峰值、日稳态稀疏窗口）已被 v5 拿走。彻底解决需动认领释放时机，超出本轮范围。
4. WRF/WFl 的真实语义已核实并建模（含 `==999` 彩票分析、阶段 0 打断=计时重置）；双发 poke 已补齐。真 DLL 落地所需的补丁点、伪代码与计数扫描早退设计见 DESIGN.md。
